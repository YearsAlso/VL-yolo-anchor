根目录作为整个仓库的编排层，将四个子模块按职责解耦并通过共享契约耦合：
- `run.py` 是 Python 侧的 CLI 入口，解析 `plan/annotate/inspect/split/full/create` 命令并组装 `TaskManager` + `Pipeline` 执行任务；`start_gui.sh` / `start_gui.ps1` 则同时拉起 `uvicorn src.api_server:app`（FastAPI 后端，监听 127.0.0.1:8765）与 `gui/` 下的 Vite 前端，构成 Tauri 开发模式。
- `python_package`（`src/`）提供核心流水线、API Server、工具函数与 Pydantic 模型；`gui_tauri_app`（`gui/`）通过 HTTP 调用同一套 API 实现四标签页界面；两者共享由 `config_prompts` 提供的全局配置与 Agent 提示词模板，并以 `tasks/<task>/` 为统一的磁盘契约（plan/annotations/inspection/dataset 等目录结构）交换数据。
- `specs_docs` 维护 Spec-Driven Development 工作流，作为实现与验收的唯一可信源；`tests` 使用 pytest 对 `src.core.pipeline`、`src.api_server`、`src.utils.*` 进行单元与集成测试，并以 `tmp_path` 隔离文件系统。
- `pyproject.toml` 在根级集中声明依赖、ruff/mypy/pytest 配置，并通过 `[tool.ruff.lint.per-file-ignores]` 与 `[tool.mypy] exclude` 把 `gui/`、`tasks/`、`prompts/` 排除在 Python 静态检查之外，使 Python 与前端代码共存于同一仓库但各自独立治理。
