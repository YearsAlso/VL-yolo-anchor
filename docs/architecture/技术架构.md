# VL-YOLO-Anchor 技术架构

> **定位**：本项目的**架构事实基线** —— 描述「现在长什么样」，不是「应该长什么样」（后者在 `.claude/rules/`），也不是「曾经决定了什么」（后者在 `docs/memory/architect-decisions.md`）。
> **比对锚点**：`docs-consistency-review` skill 以本文档为基准检查「文档 ↔ 代码」一致性；架构变更后必须更新本文档。
> **取证方式**：全部条目来自实际 `Read` / 命令输出，带 `文件:行号` 或 `文件:行号区间`。**禁止写入未实现内容**。
> **最后核对**：2026-09-27（agent 资产迁移会话）
> **状态**：已生效

## 一、系统总览

YOLO-OBB 训练计划生成 + 智能标注平台：用 VL 模型自动产出训练计划、批量标注旋转框、质检、导出可训练数据集。**训练本身不在系统内** —— 只产出 `data.yaml` 与 `train_command.txt`，由用户执行。

```
                    ┌─────────────────────────────┐
                    │  Tauri 桌面壳 / 浏览器        │  gui/src-tauri/src/main.rs (8 行)
                    │  React 18 + AntD 5 SPA      │
                    └──────────────┬──────────────┘
                                   │ axios（唯一出口 services/api.ts）
                    ┌──────────────▼──────────────┐
                    │  FastAPI  src/api_server.py  │  14 个端点 + 1 个 http 中间件
                    │  (默认 127.0.0.1:8765)       │
                    └──────────────┬──────────────┘
                                   │ 共享同一编排层
                    ┌──────────────▼──────────────┐
                    │  CLI  run.py                 │
                    └──────────────┬──────────────┘
                    ┌──────────────▼──────────────┐
                    │ src/core/pipeline.py         │  plan → annotate → inspect → split
                    │  ├─ PlanAgent      (LLM)     │
                    │  ├─ AnnotateAgent  (VL)      │
                    │  └─ InspectAgent   (规则)     │
                    └──────┬───────────────┬──────┘
                    src/utils/*        prompts/*.yaml + config/*.yaml
                           │
                    tasks/<task>/ 磁盘产物（唯一持久层，无数据库）
```

**双入口共享编排**：CLI（`run.py`）与 HTTP（`src/api_server.py`）都调用 `Pipeline`，行为一致 —— 这是设计约束，任一侧改流程必须同步另一侧的测试。

## 二、后端分层（Python 3.11+，Docker 镜像用 3.12-slim）

依赖方向**恒为**：`src/utils` ← `src/agents` ← `src/core` ← `src/api_server.py` / `run.py`，**禁止反向依赖**。

| 层 | 文件 | 行数 | 职责 |
|----|------|------|------|
| 工具 | `src/utils/obb_utils.py` | 150 | OBB 归一化/反归一化、四点↔旋转框互转、`obb_iou` —— **硬约束唯一实现处** |
| 工具 | `src/utils/image_utils.py` | 69 | `load_image`（`cv2.imdecode` + `np.fromfile`，兼容非 ASCII 路径）、`image_size`、`validate_image` |
| 工具 | `src/utils/yaml_utils.py` | 44 | `load_yaml`（**`safe_load`**）/ `save_yaml` |
| 工具 | `src/utils/file_utils.py` | 35 | `list_images()`（非递归，扩展名 `jpg/jpeg/png/bmp/tif/tiff`，目录不存在时**返回空列表而不抛异常**）、`ensure_dir()` |
| Agent | `src/agents/base_agent.py` | 69 | `BaseAgent`（`ABC`）+ `load_prompt()`：`load_yaml(self.prompt_dir / f"{name}.yaml")`（`:51`） |
| Agent | `src/agents/plan_agent.py` | 181 | 训练计划生成；`prompt["user_prompt_template"].format(...)`（`:132`） |
| Agent | `src/agents/annotate_agent.py` | 235 | 单图 VL 推理产四点框；`load_prompt("annotate_agent")`（`:73`） |
| Agent | `src/agents/inspect_agent.py` | 226 | 质检：IoU 重框、越界、尺寸异常、类别核对，产 `candidate_labels/` 建议 —— **不调用 `load_prompt`** |
| Agent | `src/agents/model_client.py` | 177 | `VLClient`（`Protocol`）、`OpenAICompatClient`（`httpx.Client` 同步）、`StubLLMClient`、`build_model_client()` |
| 编排 | `src/core/pipeline.py` | 365 | `run_step()` 分派四步；`_default_agents()` 分别构造 LLM/VL client；每步前重赋 `agent.config` |
| 编排 | `src/core/task_manager.py` | 153 | 任务目录创建/列举/读写 `task.yaml`；从 `config/task_template.yaml` 播种 |
| 入口 | `src/api_server.py` | 542 | FastAPI app、Pydantic 模型集中区、CORS、可选 bearer 鉴权中间件、文件服务端点 |
| 入口 | `run.py` | 89 | CLI 入口 |
| 配置 | `src/config.py` | 218 | 三层配置加载 + `@lru_cache(maxsize=1)` 的 `get_settings()`（`:211`） |

**关键实现事实**：

- `Settings` 是 **`BaseModel`**，不是 `BaseSettings`；优先级由**显式** `os.environ.get` + yaml 叠加实现（`load_settings()` `:155-208`），启动期 fail-fast 校验点集中可查
- FastAPI **未使用 `Depends()`** 做依赖注入；配置经模块级 `_settings` 读取
- **14 个端点全部是同步 `def`**（只有 `auth_middleware` 是 `async`）⇒ 由 anyio 线程池并发执行
- 模块级单例：`_TASKS_ROOT`、`_task_manager`、`_pipeline`（`:41-46`）—— 见「已知风险」
- HTTP 边界的内部助手：`_require_task`（`:148`）、`_safe_child`（`:170`，路径穿越防护）、`_allowed_classes`（`:~200`）、`_parse_label_file`（`:221`）

**`API_BASE` 三级解析**（`api.ts:6-14`，注释即规范）：`VITE_API_BASE` 构建参数（Docker/nginx 场景置空走同源 `/api`）→ 开发态相对路径由 Vite proxy 转发 → Tauri 生产态直连 `http://127.0.0.1:8765` 并依赖后端 CORS 白名单。

## 四、磁盘契约（`tasks/<task>/`，唯一持久层）

| 产物 | 写入方 | 读取方 | 格式 |
|------|--------|--------|------|
| `images/` | 用户投放 / CLI 导入 | `list_images`、`get_image` 文件服务、`AnnotateAgent` | 图片文件 |
| `task.yaml` | `TaskManager.save`（`:123`），从 `config/task_template.yaml` 播种（`:150`） | 各 Agent（`agent.config`）、`_require_task` | YAML |
| `plan.yaml` | `Pipeline._run_plan`（`pipeline.py:161`） | `api_server._allowed_classes`（`:208`）、计划页 | YAML（`classes` 为 `{id: name}` 映射） |
| `ai_labels/*.txt` | `AnnotateAgent` | Inspect、split、审核页 | 每行 `cls x1 y1 x2 y2 x3 y3 x4 y4`，坐标 ∈ `[0,1]` |
| `candidate_labels/*.txt` | 人工修正 / `InspectAgent._write_candidates`（`inspect_agent.py:203/:224`） | split 优先读取 | 同上 |
| `inspection_report.yaml` | `Pipeline`（`pipeline.py:193`） | 报告页 | YAML |
| `dataset/{train,val,test}/` | `Pipeline._run_split`（`:196`，标签选择经 `_pick_label` `:257`） | 导出页、用户训练流程 | 图像与标签副本 |
| `dataset/data.yaml` | `_write_dataset_yaml`（`pipeline.py:276`，写入点 `:295`） | YOLO 训练命令 | YAML |
| `dataset/train_command.txt` | `_write_train_command`（`pipeline.py:300`） | **用户在 shell 中执行** | 文本 |
| `dataset/export_summary.yaml` | `Pipeline`（`pipeline.py:252`） | `GET .../export`、导出页 | YAML |

**标签来源优先级**：`_find_label_file` 按 `("candidate_labels", "ai_labels")` 顺序查找 —— `ai_labels/` **只读**，禁止覆盖（硬约束第 2 节）。

`tasks/demo/` 是既有演示产物，保持不动；`tasks/*/images/`、`dataset/`、`ai_labels/`、`candidate_labels/` 被 `.claudeignore` 排除出上下文（含二进制大图）。

## 五、配置体系（三层，`src/config.py`）

优先级 **低 → 高**：内建默认值 → `config/global.yaml` → 环境变量。

```
ModelSettings（共享基座，:63-83）
  provider / base_url / api_key / model / timeout_s / max_retries / max_new_tokens
        │
        ├─ _overlay_model(base, model.llm 段, "VL_LLM")   :193
        └─ _overlay_model(base, model.vl  段, "VL_VL")    :194
              ↑ 只覆盖 provider / base_url / api_key / model 四项（:148-152）
```

| 键 | env | 默认 | 说明 |
|----|-----|------|------|
| 主机/端口 | `VL_ANCHOR_HOST` / `VL_ANCHOR_PORT` | `127.0.0.1` / `8765` | 生产禁 `0.0.0.0`（`:197-198`） |
| 任务根 | `VL_ANCHOR_DATA_DIR` / `VL_ANCHOR_TASKS_ROOT` | `.` / `tasks` | 容器内 `/data`；`tasks_root` 缺省取 `data_dir` 下的 `tasks` |
| 配置目录 | `VL_ANCHOR_CONFIG_DIR` | `config` | 容器内 `/app/config`（`:162`） |
| 提示词目录 | `VL_ANCHOR_PROMPTS_DIR` | `prompts` | `_env_path`（`:171`） |
| 日志目录 | `VL_ANCHOR_LOGS_DIR` | `data_dir/logs` | `:172` |
| CORS | `VL_ANCHOR_CORS_ORIGINS` | `_DEFAULT_CORS_ORIGINS` | 逗号切分，**不校验 `*`**（`:174-177`） |
| 鉴权令牌 | `VL_ANCHOR_AUTH_TOKEN` | `""`（关闭） | 可选 bearer 中间件 |
| 基座模型 | `VL_MODEL_PROVIDER` / `_BASE_URL` / `_API_KEY` / `_NAME` | — | 单端点部署只需填这组 |
| LLM 角色 | `VL_LLM_PROVIDER` / `_BASE_URL` / `_API_KEY` / `_NAME` | 继承基座 | |
| VL 角色 | `VL_VL_PROVIDER` / `_BASE_URL` / `_API_KEY` / `_NAME` | 继承基座 | |

- 默认 `provider: stub`（离线确定性输出）；`provider: remote` 时走 OpenAI 兼容端点
- 兼容旧键：`model.vl_model_name` 与角色段的 `vl_model_name` 仍被接受（`:145`、`:184`）
- **`timeout_s` / `max_retries` / `max_new_tokens` 无 env 覆盖**，且 LLM/VL 共享同一份 ⇒ 见 ADR-001 已知限制
- `get_settings()` 带 `@lru_cache(maxsize=1)`（`:211`）⇒ 进程内配置只加载一次，测试需绕缓存

`config/global.yaml`（69 行）：模型 / 阈值 / 路径 / 服务器 / 日志五段。
`config/task_template.yaml`（54 行）：类别映射 / 训练超参 / 数据集划分 / 质检规则 / 评估指标五段，`TaskManager` 用它播种每个新任务。

## 七、部署拓扑

### 本地开发

- 后端：`uv run uvicorn src.api_server:app --host 127.0.0.1 --port 8765`
- 前端：`make gui-install` + Vite dev server，`/api` 经 Vite proxy 转发（同源，无 CORS 预检、无 tainted canvas）
- 桌面：Tauri v1 壳加载 SPA，生产态 `API_BASE` 直连 `127.0.0.1:8765`
- 一键脚本：`start_gui.sh` / `start_gui.ps1`（跟踪 python 子进程 + 端口/健康检查 + 退出码传播）

### Docker（`docker compose up -d --build`）

| 服务 | 基础镜像 | 关键事实 |
|------|---------|---------|
| `backend` | `python:3.12-slim`（两阶段） | builder 用 `uv export --frozen --no-dev` 生成临时 `requirements.txt` 再 `pip install --prefix=/install`；运行层 **`USER app`**（`groupadd/useradd`，非 root）；`VOLUME /data`；`HEALTHCHECK` 打 `/api/health`；`ENV VL_ANCHOR_HOST=0.0.0.0`（容器内绑全接口，靠端口映射收口） |
| `gui` | `node:20-slim` 构建 → `nginx:1.27-alpine` | `ARG VITE_API_BASE=""` 同源；nginx `location /api/` 反代 `http://backend:8765`（`proxy_read_timeout 300s`、`client_max_body_size 100m`）；SPA fallback `try_files ... /index.html`；`/assets/` 缓存 30d |

- 端口：`backend` `"127.0.0.1:8765:8765"`（**仅回环**，注释明确要外部访问须走 TLS 反代）；`gui` `"8080:80"`（**无回环前缀** ⇒ 绑全网卡，见账本 S4）
- `env_file: .env` 配 `required: false` ⇒ 未复制 `.env.example` 也能裸起服务
- 镜像**不内置模型权重**，VL/LLM 一律走远程 OpenAI 兼容端点 ⇒ 纯 CPU 可运行
- 命名卷 `vl-data` 挂 `/data` 作为唯一可写根
- CI/发布：`.github/workflows/ci.yml`（`backend` + `frontend` 两 job）、`docker.yml`（构建 + `v*`/main 推 GHCR）、`release.yml`

## 九、已知与本文档并存的风险

本文档描述**现状**，现状含未关闭缺陷。以下摘要指向账本，完整证据见 `docs/audit-reports/README.md`：

| 编号 | 一句话 | 影响面 |
|------|--------|--------|
| A1 🔴 | 模块级 `_pipeline` 单例 + `agent.config` 就地重赋值 + 全同步端点并发 ⇒ 任务规则隔离可被击穿 | 第二节「关键实现事实」 |
| S1 🔴 | `description` 无约束 → 进提示词 → LLM 输出 → `train_command.txt` → 用户执行 | 第四、六节 |
| F1 🔴 | `Upload.Dragger beforeUpload={() => false}` 假上传 | 第三节页面层 |
| A5 🟡 | `prompts/inspect_agent.yaml` 无消费方，inspect 纯规则计算 | 第六节 |
| F2 🟡 | 前端只读 `err.message`，后端 `detail` 从不呈现 | 第三节 `api.ts` |
| S4 🟡 | gui `"8080:80"` 绑全网卡（backend 已正确收口回环） | 第七节 |
| D2 🔵 | `timeout_s`/`max_retries`/`max_new_tokens` 无 env 覆盖且双角色共享 | 第五节 |

> **关于 Dockerfile 生成 `requirements.txt`**：这是 builder 阶段的**构建中间产物**（`uv export --frozen` 从 `uv.lock` 导出，运行层用 `pip install --prefix` 后不保留依赖清单作为事实源），**不违反**「包管理只用 uv + pyproject，禁止生成 `requirements.txt`」硬约束 —— 该硬约束禁止的是把 `requirements.txt` 当作**依赖声明源**。审查时勿误判。
